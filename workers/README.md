# Firebase Spark + Cloudflare Workers Free

The Android app retains Firebase Authentication, Firestore listeners and FCM.
Trusted operations use `https://family-guard-api.tahasaleem981.workers.dev` through
Firebase's callable SDK, which supplies the existing Auth and App Check tokens.
Override the endpoint with `--dart-define=FAMILY_GUARD_API_URL=https://...`.

The Worker bundles the existing `functions/` business logic with a Firestore REST
adapter. Parent/child permissions, consent boundaries, transaction preconditions,
idempotent location uploads and deletion tombstones remain server enforced.
Google identity and App Check signatures, issuer, audience, expiry and allowed app
IDs are verified before an operation runs. Background routes require a short-lived
HMAC signature generated by the Worker; Firebase user tokens cannot invoke them.

## Local verification

From the repository root:

```sh
npm ci --prefix workers
npm run build --prefix workers
npm run test --prefix workers
npx firebase emulators:exec --project demo-family-guard --only firestore "node workers/test/run-integration.cjs"
```

Tools and npm caches must stay inside the project. Local runtime and emulator
tests use fake credentials and the `demo-family-guard` database. CI runs these
checks on feature branches and pull requests, without deployment credentials.

## Deployment configuration

`GOOGLE_SERVICE_ACCOUNT` is an encrypted Worker secret containing credentials for
a dedicated service account in `familyguard-v2-app`. Its project roles are limited
to `roles/datastore.user`, `roles/firebaseauth.admin` and
`roles/firebasecloudmessaging.admin`. Never commit credentials, copy a developer's
refresh token to the Worker or embed a service account key in the Android app.
Creating this identity, granting roles and uploading its private key require the
owner's explicit permission. Local credentials belong in the ignored `.cache/`.

After that permission and provisioning:

```sh
# Run from workers/, with project-local XDG_CONFIG_HOME and metrics disabled.
npx wrangler secret put GOOGLE_SERVICE_ACCOUNT
npx wrangler deploy

# Run from the repository root; deploy Spark-compatible indexes and rules only.
npx firebase deploy --project familyguard-v2-app --config firebase.spark.json --only firestore
```

Use `firebase.spark.json` for this deployment. The original Firebase
configuration includes Cloud Functions and billed TTL settings and must not be
used for the free backend. Spark indexes retain expiry query indexes; history
cleanup uses a `points` collection-group index. Do not enable billing or deploy
Cloud Functions as part of this path.

## Background processing and free-plan boundaries

New documents start signed HTTP jobs in separate Worker invocations. A minute
cron recovers missed fanout, pending deliveries and expired leases. Delivery and
account deletion work is idempotent; deletion stores `cleanupStage` and resumes
in bounded batches. The finite cleanup path handles the current schema's history
`points` and circle `private` subcollections. Extend those steps and their tests
when adding another private subcollection. A separate half-hour cron deletes
expired records in bounded batches instead of using paid Firestore TTL.

Workers Free currently permits 100,000 requests/day, 10 ms CPU per invocation and
50 subrequests. Background HTTP jobs also consume request allowance. Firebase
Spark permits 50,000 reads/day, 20,000 writes/day, 20,000 deletes/day and 1 GiB
storage. Limits stop service; they do not provide unlimited scaling. An empty
minute recovery sweep uses approximately eight Firestore query reads, and the
half-hour sweep uses ten. Account cleanup can take several sweeps. Expired-history
cleanup is bounded to 9,600 points/day and is not sufficient for unlimited users.

Before release, verify real-device App Check, create/join a circle, foreground and
background location sharing, notification delivery, account cleanup and actual
Cloudflare CPU/quota usage. Local runtime success does not prove production CPU
usage stays below 10 ms. Keep launch volume within measured capacity.

Sources: [Workers limits](https://developers.cloudflare.com/workers/platform/limits/),
[Firebase pricing](https://firebase.google.com/pricing).
